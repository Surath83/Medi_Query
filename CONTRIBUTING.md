# MediQuery – Contributor Guidelines 🤝

Thank you for your interest in contributing to **MediQuery**! 🚀
We welcome contributions that help improve features, performance, security, documentation, and overall user experience.

---

## 📌 How to Contribute

1. **Fork the repository**
2. **Clone your fork** to your local machine
3. **Create a new branch** for your feature or bug fix

   ```bash
   git checkout -b feature/your-feature-name
   ```
4. Make your changes and **commit with a clear message**
5. **Push to your fork** and create a Pull Request (PR)

---

## 🛠️ Contribution Areas

You can contribute in the following ways:

* Fixing bugs 🐛
* Adding new features ✨
* Improving UI/UX 🎨
* Optimizing backend performance ⚡
* Enhancing security 🔐
* Improving documentation 📄

---

## 🧑‍💻 Coding Guidelines

* Follow clean and readable coding practices
* Use meaningful variable and function names
* Write reusable and modular code
* Comment complex logic where necessary
* Ensure code passes existing tests (if any)

---

## 📂 Project Structure (Overview)

* **Frontend**: React / React Native components
* **Backend**: Node.js / Express APIs
* **Database**: MongoDB
* **Auth**: JWT-based authentication

---

## ✅ Pull Request Rules

* Clearly describe what your PR does
* Link related issues (if applicable)
* Keep PRs focused on a single change
* Avoid unnecessary formatting or refactoring

---

## 🐞 Reporting Bugs

When reporting a bug, please include:

* Bug description
* Steps to reproduce
* Expected vs actual behavior
* Screenshots or logs (if available)

---

## 📜 Code of Conduct

* Be respectful and professional
* Welcome beginners and constructive feedback
* No abusive or inappropriate language

---

## 💡 Need Help?

If you’re unsure where to start, check existing issues or reach out via discussions. We’re happy to help!

---

### ❤️ Thank You for Contributing to MediQuery!

Your efforts help make healthcare technology better and more accessible.
